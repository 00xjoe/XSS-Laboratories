✅ Solution & Explanation

What Just Happened?

The XSS payload you saved in the profile editor was retrieved from localStorage and injected directly into this page via innerHTML. The browser executed the malicious code because the application didn't sanitize the input.

Attack Impact (Real-World):

  • 🍪 Cookie Theft: Attacker steals session cookies
  • 🔑 Account Takeover: Attacker impersonates victim
  • 📧 Phishing: Fake login forms steal credentials
  • 🦠 Malware Distribution: Redirect to malicious sites
  • 💣 Defacement: Page content modified

Vulnerable Code:

// VULNERABLE: Reads from localStorage, injects with innerHTML
function displayProfile() {
    const stored = localStorage.getItem('xss_lab_profile');
    if (stored) {
        const profile = JSON.parse(stored);
        
        // DANGER: innerHTML with user data!
        document.getElementById('bioDisplay').innerHTML = profile.bio;
        
        // Also vulnerable: href can use javascript: protocol
        document.getElementById('websiteLink').href = profile.website;
    }
}

🛡️ Secure Code Fix:

// FIX 1: textContent for bio
document.getElementById('bioDisplay').textContent = profile.bio;

// FIX 2: Validate website URL
function isValidUrl(url) {
    try {
        const u = new URL(url);
        return u.protocol === 'https:' || u.protocol === 'http:';
    } catch {
        return false;
    }
}
if (isValidUrl(profile.website)) {
    document.getElementById('websiteLink').href = profile.website;
}

// FIX 3: DOMPurify for rich text bios
document.getElementById('bioDisplay').innerHTML = 
    DOMPurify.sanitize(profile.bio, {
        ALLOWED_TAGS: ['b', 'i', 'em', 'strong', 'a'],
        ALLOWED_ATTR: ['href']
    });
