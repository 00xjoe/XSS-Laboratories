Solution & Explanation

How Stored XSS Works in Profiles:

1. Attacker injects payload into profile fields
2. Payload saved to localStorage (or database in real apps)
3. Any user viewing the profile triggers the XSS
4. Payload persists until profile is deleted

Working Payloads for Bio Field:

  • <img src=x onerror=alert('XSS')> — Image error event
  • <svg onload=alert(document.cookie)> — SVG onload
  • <body onload=alert('Hacked')> — Body onload
  • <iframe src=javascript:alert(1)> — Iframe JS

Vulnerable Code:

// Profile viewer (lab5-view.html) uses innerHTML
function displayProfile() {
    const profile = JSON.parse(localStorage.getItem('profile'));
    // VULNERABLE: Direct innerHTML injection
    document.getElementById('bioDisplay').innerHTML = profile.bio;
    document.getElementById('websiteLink').href = profile.website;
}

Fix (Secure Code):

// FIX 1: Use textContent for bio
document.getElementById('bioDisplay').textContent = profile.bio;

// FIX 2: Validate and sanitize website
function safeUrl(url) {
    if (url.startsWith('https://') || url.startsWith('http://')) {
        const a = document.createElement('a');
        a.href = url;
        return a.href; // Browser-validated URL
    }
    return '#';
}

// FIX 3: DOMPurify for rich text
document.getElementById('bioDisplay').innerHTML = 
    DOMPurify.sanitize(profile.bio);
